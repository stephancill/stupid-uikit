# SF Symbol accessibility labels

iOS gives an SF Symbol image that the app has not labelled an accessibility label of its own:
`Image(systemName: "xmark")` in a SwiftUI `Button` is `Button "Close" id=xmark`, and a standalone
`Image(systemName: "star.fill")` is `Image "Favourite" id=star.fill` in British English. The guest's
automation tree (`UIAutomationTree`, docs/AUTOMATION.md) used to report only the symbol name as the
identifier. It now applies iOS 27's labels for the symbols in a table generated from the iOS 27.0
Simulator runtime.

## Where iOS's labels come from

The iOS 27.0 (24A434) Simulator runtime keeps three string tables per language in
`System/Library/PrivateFrameworks/AccessibilitySharedSupport.framework/<lang>.lproj/`:

| Table | Example |
|---|---|
| `SymbolNameOverrides.strings` | `xmark` = "Close", `magnifyingglass` = "Search" |
| `SymbolNamesAutoGenerated.strings` | `star.fill` = "favourite" (en_GB), "favorite" (en) |
| `SymbolNamesLastResort.strings` | `arrow.up.forward.square` = "Up-forward arrow in a square" |

The label is the first table's entry, in that order, with every word capitalised (words split at
spaces and hyphens). Every symbol label in the iOS 27 references (`stupidsim ui-tree`, en_GB) is
reproduced by that rule, one per table:

| Reference element | Symbol | Table |
|---|---|---|
| story: `Button "Close" id=xmark` | `xmark` | override |
| story: `Button "Volume High" id=speaker.wave.2.fill` | `speaker.wave.2.fill` | auto-generated |
| story: `Image "Favourite" id=star.fill` (twice) | `star.fill` | auto-generated (en_GB) |
| detail: `Image "Up-Forward Arrow In A Square" id=arrow.up.forward.square` | `arrow.up.forward.square` | last resort |

Apple's tables are not copied into the repository. `scripts/sf_symbol_labels_from_runtime.py` runs on
a Mac with the iOS 27 Simulator runtime installed and writes
`Sources/OpenUIKit/Automation/SymbolAccessibilityLabels.swift` with the labels of only the names in
`scripts/sf_symbol_label_names.txt` (the SF Symbols stupid social's sources name: string literals at
the reference commit that are symbol names), for `en` and the `en_GB` entries that differ:

```
python3 uikit/scripts/sf_symbol_labels_from_runtime.py \
    --runtime "<iOS 27.0.simruntime>/Contents/Resources/RuntimeRoot" \
    --names uikit/scripts/sf_symbol_label_names.txt --languages en,en_GB \
    --out uikit/Sources/OpenUIKit/Automation/SymbolAccessibilityLabels.swift
```

Names whose lookup the references cannot settle are left unlabelled and listed in the generated
file's header: legacy aliases (`doc`, `doc.fill`, `doc.on.doc`, `number`, `arrow.triangle.branch`;
iOS may resolve the alias before the lookup) and `exclamationmark.circle.fill`, which only the
last-resort table names while its unfilled form has an override ("Error"). A symbol outside the list
is unlabelled too. Unlabelled symbols keep the old behaviour: the name as the identifier.

## Language

`_UISymbolAccessibility.label(forSymbolNamed:)` uses the guest's first preferred language
(`Locale.preferredLanguages`, which the harness sets from `SSG_LOCALE` / `SSG_LANGUAGES`): the
regional table when there is one (`en-GB` -> `en_GB`), else `en`. Other English regions use `en`
(iOS may pick `en_GB` for some, e.g. `en-AU` has its own `.lproj`; not measured). Other languages have
no table and stay unlabelled.

## Where the labels apply (tree rules)

- A SwiftUI `Image(systemName:)` without an app label is `Image "<label>" id=<name>`. An app's
  `.accessibilityLabel` (an ancestor's included) wins: stupid social's muted indicator stays
  "Muted".
- Composed labels (a control's content, `.accessibilityElement(children: .combine)`) use symbol
  labels only when nothing else in the content is labelled, as iOS 27 does: the Settings rows
  `Button { HStack { Text("GitHub"); Spacer(); Image(systemName: "arrow.up.forward.square") } }` are
  `Button "GitHub"` in the reference, `Button { Image(systemName: "xmark") }` is `Button "Close"`.
  A control labelled only by symbols keeps the first symbol's name as its identifier, as the
  reference does.
- UIKit: a `UIButton` without a title whose image is a symbol, and a `UIBarButtonItem` with a symbol
  image and no title or label, take the symbol's label (identifier: the name). A titled button keeps
  its title. Not compared with a reference (stupid social's reference screens have no such UIKit
  control); it follows the same rule.
- An icon-only `Label` (`.labelStyle(.iconOnly)`) is labelled by its title, not by the symbol, as in
  SwiftUI; a titled `Label`'s symbol does not join its label.

The labels are a property of the accessibility tree, as on iOS, where UIKit's accessibility runtime
computes them when an assistive client asks: the views' stored `accessibilityLabel` stays nil.

## Verification

- `swift run symbollabelsprobe` (uikit package, native): table lookups (en_GB, en, a regional miss,
  German, an ambiguous name, an unlisted name) and the tree rules above for SwiftUI and UIKit; the
  icon-only Label check uses a title that differs from the symbol's label.
- stupid social (iOS triple, en_GB) against the iOS 27 references, tree before and after:
  - story: `Button "Volume High" id=speaker.wave.2.fill`, `Button "Close" id=xmark` and both
    `Image "Favourite" id=star.fill` now match the reference exactly (were id only).
  - detail: `Image "Up-Forward Arrow In A Square" id=arrow.up.forward.square` matches.
  - settings: unchanged and identical to the reference (`Button "stupidtech.net"`, `Button
    "GitHub"`, `Button "Advanced"`: their trailing symbols do not join the label).
  - chats, the Telegram chat, the Apron chat: unchanged (the muted row keeps the app's "Muted").
  - root: the toolbar's `Button "Settings" id=gear` and `Button "Search" id=magnifyingglass`, search:
    `Button "Filter" id=line.3.horizontal.decrease`. The references list no element for these (iOS 27
    reports the bar as an empty group), so these labels are the table's, not compared.
  - Rendered PNGs are byte-identical before and after (root, detail, settings, search, chats, Apron
    chat); the Telegram chat's before-run differed only by a composer draft left in a reused guest
    home.
